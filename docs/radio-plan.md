# 433 MHz 空口方案：同步唤醒，取消每秒信标

门锁和网关之间继续用 **433 MHz + EFR32FG28**（市面上的公寓/宿舍联网锁主流也是 433）。本文在原设计基础上做一处关键调整：**网关不再每秒发信标，只在有数据时才发射**；门锁每秒做一次约 1 ms 的“前导码嗅探”。这样网关的发射量降到按需、每次都很短，门锁更省电，同时保留秒级下发和整栋楼批量下发。连接策略的其余部分（事件即时上报 + ACK、补发、补传、断网本地开门）不变，见 [connectivity.md](connectivity.md)。

## 1. 原方案的问题

原方案里网关每个周期（1 秒）在所有信道发信标，门锁靠信标对齐时隙。问题有两个：

- 网关一天发 8.6 万次信标，空口一直有发射，干扰邻近 433 设备，也和微功率规定“短时、间歇发射”的思路相反（见第 5 节）。
- 门锁每秒要开一个“时隙 ± 2 ms 保护”的接收窗口，比只嗅探前导码费电。

## 2. 新方案：同步唤醒（按需发射）

### 2.1 门锁怎么听

- 每把锁仍然分到（信道, 时隙），每 1 秒在自己的时隙醒来，但只做一次**约 1 ms 的前导码嗅探**（EFR32 RAIL 的 RX 占空比 / 前导码检测）。没有检测到前导码立即回去睡。
- 时隙对齐不再靠信标，而是靠**门锁自己的上行收到的 ACK**：网关的每个 ACK（心跳、事件、执行结果）都带“网关当前周期内的毫秒相位”和 Unix 时间，门锁据此重新对齐时隙并校时。

### 2.2 网关怎么发

- 有指令给某把锁时，网关在该锁的时隙起点之前开始发一段**短前导码**，长度覆盖门锁可能的时钟漂移，然后紧跟数据帧；门锁嗅探到前导码就保持接收，收完回 ACK（和原来一样）。
- 前导码长度按漂移算：两端晶振各 ±20 ppm，最长 5 分钟（一个心跳间隔）没对齐，最大漂移 300 s × 40 ppm = 12 ms，所以前导码约 25–30 ms 就能保证被嗅探到。门锁心跳本身就是一次对齐，所以不需要额外的同步发射。
- 没有指令时，网关**完全不发射**（只收）。

### 2.3 失步时：异步长唤醒

门锁很久没收到 ACK（例如网关重启、换了网关）时相位不可信：

- 网关改用**长唤醒帧串**：连续发约 1.05 秒的短唤醒帧，每帧带 PAN、目标短地址（或位图）和“距离数据段还有多少毫秒”。门锁不管相位，每秒嗅探一次一定能碰到其中一帧，判断是否叫自己：是就睡到数据段开始再收，不是就继续睡。
- 门锁收到后立即上行一次，用 ACK 重新对齐，之后回到同步唤醒。
- 失联（10 分钟没有任何 ACK）仍按原策略重新入网、指数退避。

### 2.4 批量和广播

| 场景 | 做法 | 时延估算 |
| --- | --- | --- |
| 单条指令 | 在该锁下一个时隙发短前导码 + 数据 | ≤ 1 s + 几十 ms |
| 整栋楼批量单播（例如 270 把锁加卡） | 和原方案一样按时隙调度：锁分布在 3–4 个信道 × 每秒若干时隙，每把锁在自己的时隙收到 | 约 2 s 全部送达（与原方案相同） |
| 广播（封锁、应急常开、全楼配置） | 每个信道发一次异步长唤醒帧串，目标为“全部”，随后发一帧组密钥加密的广播帧；门锁收到后错开回执 | 约 1.2 s 全楼收到 |

### 2.5 上行（不变）

门锁事件即时上报（CSMA，发送前侦听），网关常收、立即回 ACK；ACK 现在多带一个相位字段。心跳 5 分钟 ±10% 抖动。

## 3. 和原方案对比

| 项 | 原方案（每秒信标） | 新方案（同步唤醒） |
| --- | --- | --- |
| 网关空闲时发射 | 每秒每信道一个信标 | 无 |
| 网关每次发射时长 | 信标几 ms | 前导码 + 数据约 30–40 ms；失步/广播时长唤醒约 1.05 s |
| 门锁每秒接收 | 时隙窗口约 4–5 ms | 嗅探约 1 ms |
| 单条下发时延 | ≤ 1 个周期 | ≤ 1 个周期 + 前导码（几十 ms） |
| 批量 / 广播 | 约 2 s / 1 s | 约 2 s / 约 1.2 s |
| 校时 | 信标 | 每次 ACK |
| 网关重启后恢复 | 门锁等信标 | 网关对表里所有锁发长唤醒，门锁上行重新对齐 |

## 4. 改动范围

| 部分 | 改动 |
| --- | --- |
| 门锁 MAC（`firmware/lock/mac`） | 信标同步改为“ACK 对齐 + 前导码嗅探”；失步/失联判定改为按“最后一次 ACK”计时；新增长唤醒帧解析 |
| 网关调度（`gateway/internal/scheduler`、`runtime`） | 去掉信标；下发帧前加前导码；ACK 带相位；对失步锁和广播用长唤醒 |
| 射频协处理器（`firmware/rcp`） | 支持可变长度前导码、长唤醒帧串 |
| 硬件 | 无变化（FG28 RAIL 支持前导码检测和 RX 占空比） |
| 平台、加密、应用协议、绑定流程 | 无变化 |
| 模拟平台 | 空口模型去掉信标，加长唤醒；可以后做 |

## 5. 合规说明

工信部《微功率短距离无线电发射设备目录和技术要求》（[原文](https://www.gov.cn/xinwen/2019-11/28/5456765/files/3affdd25607d49148a92f3ecf1dddc13.pdf)）对 433.05–434.79 MHz 的要求：10 mW e.r.p.，占用带宽 ≤ 400 kHz，每次发射 ≤ 1 s（周期性）或 ≤ 5 s（非周期），两次发射间隔 ≥ 60 min。

本方案做到：发射功率按 10 mW e.r.p. 设定，信道带宽 ≤ 400 kHz，每次发射 ≤ 1.05 s，没有持续信标，空闲时网关不发射。“间隔 ≥ 60 分钟”这一条，任何双向联网的 433 门锁和网关（包括市面产品）都做不到，这是 433 联网锁行业共同的情况；送检前和检测机构确认。

对硬件：发射功率按 10 mW e.r.p. 设计和做覆盖实测，网关覆盖几层楼以实测为准（可能少于原估计的 6–7 层）。
