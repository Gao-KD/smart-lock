# 433 MHz 空口方案：同步唤醒，取消每秒信标

门锁和网关之间继续用 **433 MHz + EFR32FG28**（市面上的公寓/宿舍联网锁主流也是 433）。本文在原设计基础上做一处关键调整（**已在固件、网关和模拟平台中实现**）：**网关不再每秒发信标，只在有数据时才发射**；门锁每秒做一次约 1 ms 的“前导码嗅探”。这样网关的发射量降到按需、每次都很短，门锁更省电，同时保留秒级下发和整栋楼批量下发。连接策略的其余部分（事件即时上报 + ACK、补发、补传、断网本地开门）不变，见 [connectivity.md](connectivity.md)。

## 1. 原方案的问题

原方案里网关每个周期（1 秒）在所有信道发信标，门锁靠信标对齐时隙。问题有两个：

- 网关一天发 8.6 万次信标，空口一直有发射，干扰邻近 433 设备，也和微功率规定“短时、间歇发射”的思路相反（见第 5 节）。
- 门锁每秒要开一个“时隙 ± 2 ms 保护”的接收窗口，比只嗅探前导码费电。

## 2. 新方案：同步唤醒（按需发射）

### 2.1 门锁怎么听

- 每把锁仍然分到（信道, 时隙），每 1 秒在自己的时隙醒来，但只做一次**约 1 ms 的前导码嗅探**（EFR32 RAIL 的 RX 占空比 / 前导码检测）。没有检测到前导码立即回去睡。
- 时隙对齐不再靠信标，而是靠**门锁自己的上行收到的 ACK**：网关的每个 ACK（心跳、事件、执行结果）都带“网关当前周期内的毫秒相位”、周期号和 Unix 时间（10 字节，用链路密钥加密认证，伪造的 ACK 不会被接受），门锁据此重新对齐时隙并校时。入网时由 Join-Accept 给出第一次相位。

### 2.2 网关怎么发

- 有指令给某把锁时，网关在该锁的时隙起点之前开始发一段**短前导码**，长度覆盖门锁可能的时钟漂移，然后紧跟数据帧；门锁嗅探到前导码就保持接收，收完回 ACK（和原来一样）。
- 前导码长度按漂移算：两端晶振各 ±20 ppm，网关记录每把锁最后一次 ACK 的时间，前导码 = 2 × 漂移（40 ppm × 距上次 ACK 的时间）+ 8 ms，上限 250 ms（`slp_sync_preamble_ms`）。心跳 30 分钟一次时最长约 150 ms；有事件上报的锁对齐得更勤，前导码更短。门锁心跳本身就是一次对齐，所以不需要额外的同步发射。
- 没有指令时，网关**完全不发射**（只收）。

### 2.3 失步时：异步长唤醒

门锁很久没收到 ACK（例如网关重启、换了网关）时相位不可信：

- 网关改用**长唤醒帧串**：连续发约 1.05 秒的短唤醒帧，每帧带 PAN、目标短地址（或位图）和“距离数据段还有多少毫秒”。门锁不管相位，每秒嗅探一次一定能碰到其中一帧，判断是否叫自己：是就睡到数据段开始再收，不是就继续睡。
- 门锁收到后立即上行一次，用 ACK 重新对齐，之后回到同步唤醒。
- 50 分钟没有 ACK（漂移超出 250 ms 前导码能覆盖的范围）时，网关只用长唤醒找它。
- 门锁某次上行没收到 ACK 就进入“可疑”状态，空闲时用心跳探测（5 s、10 s …… 封顶 5 分钟）；探测到 ACK 后发一条“重连心跳”，平台据此补发挂起指令、补传记录。可疑且 10 分钟仍没有 ACK 才重新入网、指数退避。
- 网关这边对发不到的锁也会探测（MAC PROBE，5 s → 5 分钟退避），并在 95 分钟（3 个心跳 + 余量）听不到时把锁标记离线。

### 2.4 批量和广播

| 场景 | 做法 | 时延估算 |
| --- | --- | --- |
| 单条指令 | 在该锁下一个时隙发短前导码 + 数据 | ≤ 1 s + 几十 ms |
| 整栋楼批量单播（例如 270 把锁加卡） | 和原方案一样按时隙调度：锁分布在 3–4 个信道 × 每秒若干时隙，每把锁在自己的时隙收到 | 约 2 s 全部送达（与原方案相同） |
| 广播（封锁、应急常开、全楼配置） | 每个信道发一次异步长唤醒帧串，目标为“全部”，随后发一帧组密钥加密的广播帧；门锁收到后错开回执 | 约 1.2 s 全楼收到 |

### 2.5 上行（不变）

门锁事件即时上报（CSMA，发送前侦听），网关常收、立即回 ACK；ACK 现在带相位、周期号和时间。心跳 30 分钟 ±10% 抖动（参数可配）。

### 2.6 防“假前导码”耗电攻击

前导码嗅探的弱点是：有人在附近用 433 发射机一直发前导码，门锁每秒都会被“叫醒”收一段空数据，电池很快被耗光。防护（`lock_mac_on_false_wake`）：

- 门锁统计“嗅探到前导码但没收到发给自己的有效帧”的次数。60 秒内达到 10 次，就把侦听降频为每 2 个周期一次，继续出现再翻倍，最多每 8 个周期一次（下行时延相应变为 2–8 秒，开门等本地功能不受影响）。
- 降频后门锁发一条 MAC 帧告诉网关新的侦听倍数，网关只在门锁会听的周期里安排下发；同时上报告警 `RF_JAM`（“无线耗电攻击”），宿管能在平台看到。
- 连续 5 分钟没有假唤醒，倍数减半，逐步回到每秒侦听。
- 演示 `wake-jam`：对一把锁注入 25 次假前导码，侦听降到每 4 个周期以下，之后远程开门仍然成功。

### 2.7 在线状态和电量：门锁主动上报，平台不轮询

平台**不定时下发查询**去问每把锁的电量和在线状态，原因是：每次查询都要网关发一次前导码 + 数据、门锁多收一次再回一次，一栋楼几百把锁按分钟级轮询，网关发射量和门锁耗电都会成倍增加，而得到的信息门锁本来就会主动送上来。做法：

| 信息 | 怎么来 | 平台看到的时效 |
| --- | --- | --- |
| 电量、电压、门磁、反锁、凭证数、时间 | 心跳（默认 30 分钟，±10% 抖动；严重低电时放慢 4 倍） | ≤ 30 分钟 |
| 低电、开门、告警、门磁变化 | 事件发生时立即上报，每条上报都带最新电量等级 | 秒级 |
| 在线 | 任何上行（心跳、事件、执行结果）都刷新“最后上行时间”；95 分钟（3 个心跳 + 余量）没有任何上行判离线 | ≤ 95 分钟；网关探测失败会更早发现 |
| 恢复在线 | 门锁重连后立即发“重连心跳”，平台标记在线并补发挂起指令 | 秒级 |
| 需要即时确认时 | 平台仍可对单把锁“查询状态”或对整栋楼“全部查询”（现有接口），按需使用，不做定时任务 | ≤ 1–2 秒 |

心跳间隔是门锁参数（`CFG_HEARTBEAT_S`），平台可以下发修改；改短会直接缩短电池寿命，建议不低于 10 分钟。

## 3. 和原方案对比

| 项 | 原方案（每秒信标） | 新方案（同步唤醒） |
| --- | --- | --- |
| 网关空闲时发射 | 每秒每信道一个信标 | 无 |
| 网关每次发射时长 | 信标几 ms | 前导码（8–250 ms，按距上次 ACK 的时间）+ 数据；失步/广播时长唤醒约 1.05 s |
| 门锁每秒接收 | 时隙窗口约 4–5 ms | 嗅探约 1 ms |
| 单条下发时延 | ≤ 1 个周期 | ≤ 1 个周期 + 前导码 |
| 批量 / 广播 | 约 2 s / 1 s | 约 2 s / 约 1.2 s |
| 校时 | 信标 | 每次 ACK |
| 网关重启后恢复 | 门锁等信标 | 网关对表里所有锁发长唤醒，门锁上行重新对齐 |

## 5. 合规说明

工信部《微功率短距离无线电发射设备目录和技术要求》（[原文](https://www.gov.cn/xinwen/2019-11/28/5456765/files/3affdd25607d49148a92f3ecf1dddc13.pdf)）对 433.05–434.79 MHz 的要求：10 mW e.r.p.，占用带宽 ≤ 400 kHz，每次发射 ≤ 1 s（周期性）或 ≤ 5 s（非周期），两次发射间隔 ≥ 60 min。

本方案做到：发射功率按 10 mW e.r.p. 设定，信道带宽 ≤ 400 kHz，每次发射 ≤ 1.05 s，没有持续信标，空闲时网关不发射。“间隔 ≥ 60 分钟”这一条，任何双向联网的 433 门锁和网关（包括市面产品）都做不到，这是 433 联网锁行业共同的情况；送检前和检测机构确认。

对硬件：发射功率按 10 mW e.r.p. 设计和做覆盖实测，网关覆盖几层楼以实测为准（可能少于原估计的 6–7 层）。
