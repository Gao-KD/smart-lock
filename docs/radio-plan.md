# 无线方案与频段合规（选型决定）

## 结论

**门锁与网关之间的网络改用 2.4 GHz 的 BLE 5.4 PAwR（Periodic Advertising with Responses，带响应的周期广播），不再用 433 MHz 私有协议。** 门锁主控从 EFR32FG28 换成 2.4 GHz 单频的 EFR32BG24 系列（Secure Vault High 型号）。一颗芯片、一根 2.4 GHz 天线同时负责楼宇组网、手机蓝牙钥匙和安装师傅绑定。

现有的系统设计（相位同步的周期侦听、每把锁每秒醒来一次、指令 ≤ 1 个周期到锁、两层加密、平台下发与补发）全部保留，只是把“433 MHz 上自己做的时隙 MAC”换成蓝牙标准里现成的、为同一个问题设计的 PAwR。

## 为什么 433 MHz 不行

工信部《微功率短距离无线电发射设备目录和技术要求》（[原文 PDF](https://www.gov.cn/xinwen/2019-11/28/5456765/files/3affdd25607d49148a92f3ecf1dddc13.pdf)）里，433.05–434.79 MHz 属于“通用无线遥控设备”：功率 10 mW e.r.p.，周期性发射每次 ≤ 1 秒、两次之间至少间隔 60 分钟。我们的网关每秒发一次信标，门锁随时上报事件，这是持续组网，不是遥控，按目录不合规。

## 候选方案对比

| 方案 | 合规性 | 秒级批量下发 | 门锁功耗 | 覆盖 | 硬件复杂度 | 结论 |
| --- | --- | --- | --- | --- | --- | --- |
| 433 MHz 私有（原方案） | ✗ 遥控条目，1 s / 60 min | 能 | 低 | 好（每 6–7 层一台网关） | Sub-GHz + BLE 双射频 | 放弃 |
| 470–510 MHz 私有 | △ 目录里是“民用计量仪表”：50 mW、楼宇内组网、单次发射 ≤ 1 s、必须 LBT、同一时刻单信道发射。门锁不是计量仪表，能否套用要看当地无线电管理机构 | 能，但多信道并发受“单信道发射”限制，网关吞吐下降 | 低 | 好 | 同上 | 备选（见末节） |
| LoRa（470–510） | 同上 | ✗ 速率低，一栋楼几百条指令要几十秒以上 | 低 | 最好 | 外挂模组 | 不满足秒级 |
| Wi-Fi | ✓ | 常在线才能秒级，电池撑不住 | ✗ 高 | 好 | 外挂模组 | 不满足续航 |
| Zigbee / Thread（2.4 GHz） | ✓ | 休眠终端靠轮询，批量时延不可控 | 中 | 中，靠路由节点 | 协议栈重 | 不选 |
| **BLE 5.4 PAwR（2.4 GHz）** | **✓ 蓝牙是标准无线技术，按 2.4 GHz 无线局域网/蓝牙设备做型号核准（SRRC）即可，无占空比限制** | **✓ 标准就是为“一个基站秒级管理成千上万低功耗终端”设计的（电子价签 ESL 标准就建在它上面）** | **低：每把锁每周期只在自己的子事件醒来几毫秒，和原方案同一个思路** | 中：2.4 GHz 穿墙弱于 433，需要每层（或每 40–60 间）一台网关 | **最低：单频 2.4 GHz，一根天线** | **采用** |

所以“最高效”的合规方案是 PAwR：合规路径最清楚（普通蓝牙产品的型号核准流程）、时延模型和原设计一致、硬件最简单、芯片和网关成本更低；代价是网关数量从“每 6–7 层一台”变成“每层一台”。

## PAwR 怎么对应原来的设计

PAwR 的结构（Silicon Labs 文档 [Use Case #9](https://docs.silabs.com/bluetooth/9.1.0/bluetooth-low-power-optimization/use-case-9-i-want-to-exchange-data-with-many-low-power-peripheral-devices)）：广播方（网关）按固定的周期间隔发送 PAwR 事件；每个事件最多 128 个子事件；每个子事件里网关先发一包数据，随后最多 255 个响应时隙供终端回复。一条 PAwR 链路理论上可以和 128 × 255 = 32,640 个设备双向通信。

| 原设计（433 MHz） | PAwR 实现 |
| --- | --- |
| 周期 1 s，网关每周期发信标 | PAwR 周期间隔 1 s；周期广播本身就是信标，终端同步后按它对齐时钟 |
| 每把锁分到（信道, 时隙），只在自己的时隙醒来 | 每把锁分到（子事件号, 响应时隙号），只同步自己的子事件：每秒收一包 + 必要时在自己的响应时隙回一包 |
| 网关在锁的时隙下发指令，锁立即回 ACK | 网关把指令放进该锁所在子事件的数据包；锁在同一子事件的响应时隙回执行结果/ACK |
| 多信道并发提高吞吐 | 一个网关可以跑多条 PAwR 链路（多颗射频芯片），每条 1 s 内 128 个子事件、每个子事件一包数据可以带 1–2 条指令；BLE 自带跳频 |
| 事件即时上报 | 锁在下一次自己的响应时隙上报（≤ 1 s）；告警类可以额外用可连接广播立即上报 |
| 广播（封锁、应急常开） | 网关把广播指令复制进下一个周期的所有子事件，1 s 内全楼送达 |
| 入网 | 锁扫描网关的扩展广播并同步周期广播；每个子事件留几个空闲响应时隙给入网请求；网关分配子事件和时隙（替代 Join-Accept） |
| 失步、失联、退避重连 | 失去周期同步 → 重新扫描同步；策略和时间参数照旧 |
| 链路层 AES-CCM（K_link）+ 端到端（K_app） | 保留：PAwR 广播本身不加密，我们的两层加密照常包在数据里（见 `common/slp/include/slp/secure.h`）。网关和中继仍然看不到端到端内容 |

**时延与吞吐估算**（需要用开发板实测确认）：周期 1 s 时，单把锁的指令最多等 1 个周期；一条 PAwR 链路每秒约 128–256 条指令，一台网关 2 条链路即可覆盖一层 40–80 间房的批量下发，一层楼全部送达约 1–2 秒。和原方案“单网关 270 把锁约 2 秒”同一量级，因为每台网关管的锁变少了。

**功耗**：门锁每秒醒来一次收一包（几毫秒，2.4 GHz 接收电流和原 Sub-GHz 接收同量级），和原方案的功耗模型基本一致，基础版平均电流目标仍按 ≈ 70 µA 量级，需实测。

## 对系统各部分的影响

| 部分 | 变化 |
| --- | --- |
| 门锁硬件 | 主控换 EFR32BG24（Secure Vault High 型号）；去掉 Sub-GHz 匹配网络和 433 天线；2.4 GHz 天线需要考虑穿门：预留 IPEX 座，天线可以放在前面板一侧。详见 [hardware/handoff.md](hardware/handoff.md) |
| 网关硬件 | 每层一台（或按房间数），吸顶装在走廊；Linux 主机 + 2 颗 BG24 射频协处理器 + 以太网/PoE（4G 可选，按楼栋汇聚） |
| 协议应用层（`common/slp` 的 TLV、两层加密、去重、防重放） | 不变 |
| 门锁 MAC（`firmware/lock/mac`） | 信标同步、时隙计算换成 PAwR 同步和子事件回调；上行确认队列、失联判定、退避逻辑保留 |
| 网关调度（`gateway/internal/scheduler`、`locktable`） | （信道, 时隙）网格换成（链路, 子事件, 响应时隙）网格；优先级调度、紧急插队逻辑不变 |
| 射频协处理器（`firmware/rcp`） | 换成 BG24 上跑 PAwR 广播方 |
| 平台 | 不变 |
| 模拟平台 | 空口模型改成“子事件”，用于验证调度；可以后做 |
| 绑定流程（[provisioning.md](provisioning.md)） | 不变；网关批量绑定和安装 App 绑定现在走同一种射频 |

## 合规要点（给硬件和认证）

- 门锁和网关都按 2.4 GHz 蓝牙设备做无线电发射设备型号核准（SRRC）。2.4 GHz 频段的功率等要求以工信部 2021 年关于 2400/5100/5800 MHz 频段管理的通知（工信部无〔2021〕129 号）为准，硬件同事和检测机构确认具体限值（需核实）。
- 门锁发射功率按 +10 dBm 设计即可（BLE 常规），网关可以到更高功率等级，以核准限值为准。
- NFC 13.56 MHz 读卡在微功率目录 C 类内（10 m 处磁场 ≤ 42 dBµA/m），没有问题。

## 风险和备选

| 风险 | 应对 |
| --- | --- |
| 钢质防火门（公租房）对 2.4 GHz 衰减大 | 天线放前面板一侧或门边缘；网关装在走廊、正对门；必要时用 BLE Coded PHY（长距离模式）提升链路预算（PAwR 下 Coded PHY 的支持情况需在 SDK 中核实）；第一轮覆盖实测必须包含钢门 |
| PAwR 在 BG24 上的子事件数、响应时隙数、最短周期等实际参数 | 开发板实测，见下面的验证步骤 |
| 网关数量增加 | 网关只要一颗小 Linux SoC + 2 颗 BG24，成本远低于原来带 3–4 路 Sub-GHz 的网关；按楼层 PoE 供电 |
| 实测覆盖不达标 | 备选：470–510 MHz 私有方案（沿用原 433 设计，换频点 + 加 LBT + 单信道发射），前提是先取得当地无线电管理机构书面认可。届时换回 EFR32FG28 |

## 验证步骤（第一阶段就做，用开发板）

1. 2 块 BG24 开发板 + Silicon Labs PAwR / ESL 示例：一块当网关，另一块当门锁，测同步后每秒唤醒的平均电流。
2. 用多块开发板（或一块板模拟多个响应时隙）测 1 s 周期下子事件数、每子事件数据长度和端到端时延。
3. 在真实宿舍楼测：走廊吸顶网关到最远房间门锁（木门、钢门各一）的 RSSI 和丢包，分别用 1M PHY 和 Coded PHY。
4. 结果交回后定：每层网关数量、PHY、周期间隔。
