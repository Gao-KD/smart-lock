# 硬件交付说明（给硬件工程师）

本文是交给硬件工程师的一份“需求 + 分工”说明：用什么平台、要采购哪些模块和频段器件、主板要留哪些接口、软件这边会交付什么、硬件那边负责什么、什么时候算交付完成。系统整体设计见 [README](../../README.md)，空口方案见 [radio-plan.md](../radio-plan.md)，功能见 [lock-features.md](../lock-features.md)，连接与功耗见 [connectivity.md](../connectivity.md)，出厂状态和绑定流程见 [provisioning.md](../provisioning.md)。已有的 [测试购买清单](purchase-list.md) 和 [嘉立创 EDA 指南](pcb-guide.md) 仍然有效，本文在它们基础上补齐指纹、人脸、键盘、产测和量产烧录。

> 价格和型号的现货情况没有核对，下单前请向代理商询价确认。标注“需核实”的地方请硬件同事以数据手册和检测机构意见为准。

## 1. 一句话需求

做一块门锁后面板主板 + 一块前面板小板，装进标准 24×240 锁体的公寓锁壳：

- 主控是**一颗 EFR32FG28**，它同时负责 Sub-GHz 私有网络（到楼宇网关）和 BLE（手机蓝牙钥匙、安装师傅绑定）。门锁上**不放** Wi-Fi、LoRa、4G 模块。
- 开门方式：校园卡（13.56 MHz NFC）、触摸键盘密码、指纹（第二版起贴片）、人脸（高配版）、手机蓝牙、机械钥匙。
- 4 节 AA 供电（基础版），人脸版改锂电池包。基础版平均电流目标约 71 µA。
- 另做一块网关射频板：同一颗 EFR32FG28 当射频协处理器，3~4 路，经 UART/USB 接 Linux 主机。

## 2. 平台选型

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 门锁主控 | Silicon Labs `EFR32FG28B322F1024IM68-A`（QFN68） | 单芯片 Sub-GHz + BLE 5.x；B = Secure Vault High（密钥不出芯片、防篡改）；322 = 20 dBm Sub-GHz + 10 dBm BLE；1 MB Flash 够放双区 OTA |
| 门锁 SDK | Simplicity SDK（RAIL、Bluetooth、PSA Crypto、NVM3、FreeRTOS），Gecko Bootloader | 软件这边固定 SDK 版本，硬件调试时用同一版本 |
| 网关射频 | 同一颗 EFR32FG28（可以用 `B3xx` 或不带 Secure Vault High 的便宜型号，需核实） | 和门锁同一套射频代码，省维护 |
| 网关主机 | 任意 ARM Linux 工控板（4 核、1 GB 以上、以太网、可选 4G Cat.1） | 跑 `gateway` 程序，开发期可以用树莓派 |
| 不采用 | Wi-Fi（电池扛不住常在线）、LoRa（速率低，做不到秒级批量下发）、Zigbee/Thread（协议栈重，批量时延不可控） | 见 [connectivity.md](../connectivity.md) |

### 2.1 频段与发射功率

| 射频 | 频段 | 要求 |
| --- | --- | --- |
| 楼宇组网 | 433.05–434.79 MHz | 发射功率按 **10 mW e.r.p.** 设计（微功率目录上限），占用带宽 ≤ 400 kHz；每次发射 ≤ 1 s |
| 手机蓝牙、安装绑定 | 2.4 GHz BLE | 常规 BLE 功率 |
| 读卡 | 13.56 MHz | 微功率目录 C 类，NFC 读卡没有问题 |

空口改为“同步唤醒”：网关不再每秒发信标，只在有数据时发射，门锁每秒嗅探约 1 ms 前导码，见 [radio-plan.md](../radio-plan.md)。对硬件的影响：

1. 覆盖实测按 10 mW e.r.p. 做，一台网关覆盖几层楼以实测为准。
2. 测睡眠电流时加上“每秒 1 ms 前导码嗅探”这一项。

## 4. 接口与引脚要求

具体引脚号由硬件同事按 PCB 走线定，填进第 4.4 节的引脚表交回。软件这边对接口的约束如下：

### 4.1 信号清单

| 外设 | 总线 / 信号 | 唤醒要求 | 备注 |
| --- | --- | --- | --- |
| NFC FM17550 | SPI（SCK/MOSI/MISO/CS）+ IRQ + NRST + 电源使能 | IRQ 需能把芯片从 EM2 唤醒 | 低功耗寻卡由读卡芯片自己做 |
| 触摸键盘 | I²C（SCL/SDA）+ INT | INT 必须能从 EM2 唤醒；建议也能从 EM4 唤醒 | 有人碰键盘就唤醒，并触发 BLE 广播 30 秒 |
| 指纹 | UART（TX/RX）+ 触摸检测 + 电源使能 | 触摸检测必须能从 EM2 唤醒 | 建议独占一路 EUSART |
| 人脸 | UART（TX/RX）+ 电源使能 + 升压使能 + 接近感应中断 | 接近感应中断从 EM2 唤醒 | 与指纹不同时工作也要分开 UART |
| 电机 | DRV8837 IN1/IN2 + nSLEEP + 采样电阻 → ADC | — | ADC 通道要能在驱动期间快速采样 |
| 门磁霍尔 | GPIO | EM2 唤醒 | |
| 反锁 / 防撬 / 机械钥匙 | GPIO ×3 | EM2 唤醒 | 防撬建议也接 EM4 唤醒脚 |
| 设置键（复位/配网） | GPIO | EM2 + EM4 唤醒 | 装在室内侧电池盒里，门外按不到 |
| 电池电压 | 分压使能 GPIO + ADC | — | |
| 蜂鸣器 | 定时器 PWM | — | |
| RGB LED | GPIO ×3 或 PWM | — | |
| 调试 | SWCLK、SWDIO、RESETn、VCOM TX/RX | — | 产测必须能访问 |
| 前后板 FPC | 上述前面板信号 + 3.3 V、电池电压、GND | — | 预留 2–4 根备用线 |

### 4.2 EFR32 Series 2 的引脚规则（画板前请核对数据手册）

- 需要在 EM2 深睡里继续工作的低功耗外设（例如低功耗定时器输出）只能放在 **Port A / Port B**。
- EM4 唤醒只能用数据手册标注为 `EM4WU` 的引脚，设置键和防撬尽量放在这些脚上。
- 射频引脚、晶振引脚照抄参考设计，不要复用。
- 每路负载开关的使能脚上电默认要是“关”（加下拉），避免复位期间模组被打开。

### 4.3 设置键的约定

设置键是出厂复位和蓝牙配网的唯一物理入口，必须装在**室内侧**（电池盒内或后面板内），门外无法触及。行为见 [provisioning.md](../provisioning.md) 第 6 节。

### 5.3 共同负责

- 覆盖实测：在真实宿舍楼里测每层楼最远门锁到网关的 RSSI 和丢包（软件提供测试固件和网关程序）。
- 续航评估：用实测电流套进 connectivity.md 的功耗模型，算电池寿命。
- 绑定流程联调：出厂状态、设置键、断电恢复（见 provisioning 文档第 8 节的测试用例）。

## 6. 验收标准（第一版主板）

| 项 | 标准 |
| --- | --- |
| 睡眠电流（EM2，仅 RTC） | ≤ 3 µA（不含每秒 1 ms 前导码嗅探） |
| 平均电流（基础版，每秒侦听 + 5 分钟心跳 + 每天 10 次开门） | ≈ 71 µA 量级，实测值交回 |
| 433 发射功率、频偏 | 10 mW e.r.p. 以内，设定功率 ±1 dB；频偏 ≤ ±10 ppm |
| 覆盖 | 10 mW e.r.p. 下，网关覆盖范围内最远门锁丢包 < 1% |
| 读卡 | 校园卡 3 cm 内 100 次 100% 读出，寻卡电流按 FM17550 低功耗模式 |
| 电机 | 4.4 V 低电压下仍能可靠驱动；堵转能被检测 |
| 负载开关 | 关闭后指纹/人脸/读卡支路漏电 ≤ 0.5 µA |
| 设置键 | 门外不可触及；长按能从 EM4 唤醒 |
| 掉电保护 | 电池电压跌到 BOD 阈值时不损坏 NVM（软件配合，见 provisioning 第 7 节） |
| 调试 | 每块板都能经测试点烧录和读 EUI |

## 7. 建议节奏

1. 第 1–2 周：开发板 + 模块飞线，跑通读卡、键盘、电机、指纹握手；同时在真实楼里测 433 覆盖（10 mW e.r.p.）。
2. 第 3–4 周：原理图（主板 + 前面板），射频照抄参考设计，交代理商 FAE 评审；填引脚表。
3. 第 5–6 周：第一版打样 5 套，跑自检固件和射频测试固件，调匹配。
4. 第 7–8 周：功耗实测、覆盖实测、绑定流程联调；人脸版样机。
5. 之后：第二版改板、产测夹具、小批量（50 把）试装一层楼。
