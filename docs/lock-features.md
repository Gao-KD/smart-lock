# 门锁功能设计（功能点清单）

本文列出门锁的全部业务功能、每个功能在协议里怎么表达、门锁固件怎么执行，以及为什么这样适配校园宿舍和公租房的批量管理场景。

功能范围参考了涂鸦等主流智能门锁平台公开的开发者文档（门锁功能点/DP 列表、成员与开锁方式管理、临时密码与离线密码、告警与开门记录、远程开门、反锁等），**只借鉴功能清单，协议、算法和代码都是本项目自己的**：空口是 433 MHz 私有协议（[README](../README.md)），所有指令端到端 AES-128-CCM 加密，网关看不到内容。

和面向家庭的单锁方案相比，本项目的取舍：

- **平台是唯一的管理入口**：凭证由平台批量下发，门锁不提供本地按键“添加管理员/录入密码”的流程（避免一栋楼几百把锁各自被人改设置）。
- **一切以秒级批量为前提**：每条指令都很短（单帧 ≤ 127 字节），按用户、按楼栋批量操作，而不是逐个凭证操作。
- **断网也能开门**：卡、密码、离线密码、手机蓝牙都在门锁本地校验；记录先存在锁里，恢复后补传。连接策略见 [connectivity.md](connectivity.md)。

## 1. 开锁方式（凭证）

| 功能 | 协议 | 门锁行为 | 校园/公租房适配 | 状态 |
| --- | --- | --- | --- | --- |
| 校园卡 | `CRED_ADD` 类型 1，ID = 卡 UID（4/7/10 字节） | 只比对 UID，不读扇区 | 沿用学校一卡通，不需要发新卡 | 已实现，演示 `card-unlock` |
| 固定密码 | 类型 2，ID = 6~10 位数字 | 键盘输入后比对 | 公租房住户常用 | 已实现，`password` |
| 虚位密码（防偷看） | 无需额外字段 | 输入最多 16 位，只要其中连续包含真实密码就通过 | — | 已实现，`password` |
| 一次性 / N 次密码 | TLV `USES`（u16，1 = 一次性） | 每用一次减 1，到 0 自动删除 | 访客、送水、维修 | 已实现，`password` |
| 限时凭证 | `VALID_FROM` / `VALID_TO` | 窗口外返回 `EXPIRED` | 学期卡、毕业离校日自动失效 | 已实现，`card-manage` |
| 周期凭证 | TLV `SCHEDULE`：星期掩码 + 每天起止分钟（本地时间，支持跨午夜） | 时段外返回 `OUT_OF_SCHEDULE` | 保洁只在工作日 8:00-10:00 | 已实现，`password` |
| 离线密码 | 不下发；平台用门锁 K_app 算 10 位数 | 本地反向搜索签发小时校验 | 网关故障、锁不在线时宿管电话告知维修人员 | 已实现，`offline-password` |
| 手机蓝牙钥匙 | 不下发；平台签发 17 字节令牌 | BLE 连接后出示令牌，本地验签 | 网络故障兜底；宿管令牌可在封锁时开门 | 逻辑已实现（模拟里用控制命令代替 BLE 连接），`ble-fallback` |
| 远程开门 | `UNLOCK`，可带 `DURATION_S` | 驱动离合，到时自动落锁 | 宿管远程开门 | 已实现，`remote-unlock` |
| 指纹 / 人脸 | 类型 3/4，ID = 模组里的模板号 | 接口已留 | 按决定后续再做 | 预留 |

### 离线密码算法

```
密码 = K D MMMMMMMM（10 位）
  K  种类：0 一次性（6 小时内用一次）；1~7 限时（1/4/8/24/72/168/720 小时内可反复用）；9 清除码
  D  序号 0~9（同一小时内可签发 10 个）
  M  MAC64(K_app, "OFP" | K | D | 签发小时) mod 10^8
```

- 门锁从“当前小时”往回逐小时计算，命中即有效，不需要任何下发；一次性密码和清除码用过后记在锁内，不能再用。
- 清除码让“签发小时 ≤ 清除码小时”的所有离线密码作废（维修结束后让密码失效）。
- MAC 用的是端到端密钥 K_app（EFR32 上在 Secure Vault 里，固件 `hal_app_mac`），所以只有平台能算；8 位随机部分加上“连续 5 次错误冻结 3 分钟”，暴力猜测不可行。
- C 实现：`firmware/lock/credential/offline_pwd.c`；Go 实现：`common/slpgo/slp/local.go`；两边有同一组已知答案测试。

### 手机蓝牙钥匙

令牌 = `USER_ID(4) | VALID_TO(4) | FLAGS(1) | MAC(8)`，MAC = K_app 下对 `"BLE" | 前 9 字节` 的 MAC。`FLAGS` 含管理员位时以“宿管”身份开门（封锁期间也能开）。
真实设备上手机通过 BLE 连上门锁后，门锁先发随机挑战，手机用令牌派生的会话密钥应答，令牌不能被嗅探重放；模拟平台里简化为直接出示令牌。

## 2. 成员管理

每个凭证都属于一个平台用户（`USER_ID`）。为了批量场景，门锁支持按用户整体操作：

| 功能 | 协议 | 说明 |
| --- | --- | --- |
| 冻结 / 解冻成员 | `USER_FREEZE`（`USER_ID`，`FREEZE`=1/0） | 该用户的卡、密码一起失效 / 恢复，返回 `FROZEN`；公租房欠费常用 |
| 删除成员 | `USER_DEL`（`USER_ID`） | 退宿、退租一条指令删光该用户全部凭证，回复里带剩余凭证数 |
| 清空凭证 | `CRED_CLEAR` | 毕业季整栋楼批量清空（控制台“全楼清空凭证”） |
| 删除单个凭证 | `CRED_DEL` | 幂等，删不存在的也返回 OK |
| 管理员凭证 | 凭证标志 `ADMIN` | 宿管卡/密码在封锁期间仍可开门 |
| 胁迫凭证 | 凭证标志 `DURESS` | 照常开门，同时静默上报胁迫告警 |

## 3. 门锁状态与传感器

| 功能 | 协议 | 门锁行为 |
| --- | --- | --- |
| 锁状态 | `LOCK_STATE`：上锁 / 开门 / 封锁 / 应急常开 / 故障 | 心跳、状态查询、执行结果都带 |
| 室内反锁 | `EVT_DOOR` 带 `DOUBLE_LOCK`；状态标志位 | 反锁后门外所有开门方式（卡、密码、远程、蓝牙）都返回 `DOUBLE_LOCKED`，不计入试错；机械钥匙不受影响 |
| 门磁 | `EVT_DOOR` 带 `DOOR` | 开门后一关门立即落锁（不必等 5 秒）；门开着超过设定时间告警 |
| 封锁 / 应急常开 | `LOCKDOWN` / `EMERGENCY` / `RELEASE`，可广播 | 已有，演示 `broadcast` |
| 电量 | `EVT_BATTERY`、心跳里的 `BATTERY_MV`/`BATT_LEVEL` | 低电 / 严重低电 / 恢复，带回差 |

## 4. 告警（`EVT_ALARM`，TLV `ALARM`）

| 值 | 告警 | 触发 | 门锁本地动作 |
| --- | --- | --- | --- |
| 1 | 多次试错 | 连续 N 次（默认 5）未知卡/错误密码 | 读卡和键盘冻结 M 秒（默认 180），期间返回 `LOCKED_OUT`；远程开门不受影响 |
| 2 | 防撬 | 面板防撬开关 | 本地声光报警 |
| 3 | 胁迫 | 使用胁迫凭证 | 照常开门，不做任何本地提示 |
| 4 | 门未关好 | 门开着超过设定秒数（默认 120） | 本地提示一次 |
| 5 | 机械钥匙开门 | 应急钥匙孔微动开关 | — |
| 6 | 电机故障 | 离合连续两次驱动失败 | 进入 FAULT，下条指令重试 |
| — | 低电量 | 单独的 `EVT_BATTERY` | 开门时额外提示音 |

## 5. 开门记录

- 门锁把每条开门（成功或失败）、告警、门磁/反锁、访客请求、电量变化都写入**记录日志**，带递增序号 `LOG_SEQ`。锁内保留最近 128 条（EFR32 上存 NVM3），待上行队列 16 条。
- 记录里**不出现密码数字**：密码开门只上报用户号，离线密码只上报种类和序号，卡只上报 UID。
- 平台按 `LOG_SEQ` 去重并检测缺口；心跳也带最新序号。缺口持续 3 秒以上就下发 `READ_LOG`（起始序号 + 条数），门锁把这些记录重新排队上报，带 `REPLAYED` 标记，平台事件里显示为“[补传]”。演示 `offline-records`。
- 记录的来源（`SOURCE`）：卡、密码、指纹、人脸、蓝牙、远程、宿管。

## 6. 远程开门确认（访客呼叫）

- 参数 `CFG_REMOTE` 关闭后，平台直接下发的远程开门被门锁拒绝（`NEED_REQUEST`）。适合公租房：住户不希望管理方随时能开门。
- 访客按门锁上的呼叫键 → 门锁上报 `EVT_UNLOCK_REQ`（请求号 + 60 秒窗口）→ 住户/宿管在 App 上批准 → 平台下发带 `REQ_ID` 的 `UNLOCK`，门锁核对请求号和窗口后开门，一次请求只能用一次。
- 应急常开（消防）不受此开关影响。演示 `unlock-request`。

## 7. 参数配置（`CONFIG`，只改带上的字段）

| TLV | 参数 | 默认 | 范围 |
| --- | --- | --- | --- |
| `CFG_AUTOLOCK_S` | 自动落锁时间 | 5 秒 | 1~600 |
| `CFG_VOLUME` | 提示音量 | 2 | 0 静音 ~ 3 |
| `CFG_REMOTE` | 允许直接远程开门 | 1 | 0/1 |
| `CFG_WRONG_LIMIT` | 试错次数上限 | 5 | 0 = 不限 |
| `CFG_LOCKOUT_S` | 试错冻结时间 | 180 秒 | ≤ 3600 |
| `CFG_HEARTBEAT_S` | 心跳间隔 | 300 秒（模拟 30 秒） | ≥ 10 |
| `CFG_DOOR_ALARM_S` | 门未关告警时间 | 120 秒（模拟 30 秒） | 0 = 关闭 |

整栋楼统一配置是一次批量单播（`POST /api/buildings/1/config`），360 把锁约 3 秒全部生效，演示 `config`。状态查询和配置的回复里带当前的自动落锁时间和远程开门开关，平台据此核对。

## 8. 结果码

`OK`、`EXPIRED`（过期/已用过）、`DUPLICATE`（重发去重）、`DENIED`（未知凭证）、`BAD_PARAM`、`FULL`、`HW_FAULT`，以及新增的 `DOUBLE_LOCKED`（已反锁）、`LOCKED_OUT`（试错冻结中）、`FROZEN`（成员冻结）、`OUT_OF_SCHEDULE`（不在允许时段）、`NEED_REQUEST`（远程开门需访客请求）。

| 方向 | 码 | 名称 | 主要 TLV |

| 下行 | 0x13 | USER_DEL | USER_ID → 回复 COUNT、CRED_COUNT |
| 下行 | 0x14 | USER_FREEZE | USER_ID、FREEZE → 回复 COUNT |
| 下行 | 0x20 | READ_LOG | LOG_SEQ（起始）、COUNT → 回复 COUNT |

| 上行 | 0x91 | EVT_ALARM | ALARM、CRED_TYPE、USER_ID、LOG_SEQ |
| 上行 | 0x93 | EVT_HEARTBEAT | 新增 FLAGS、LOG_SEQ、HB_REASON |
| 上行 | 0x94 | EVT_DOOR | DOOR、DOUBLE_LOCK、LOG_SEQ |
| 上行 | 0x95 | EVT_UNLOCK_REQ | REQ_ID、DURATION_S（窗口）、LOG_SEQ |
